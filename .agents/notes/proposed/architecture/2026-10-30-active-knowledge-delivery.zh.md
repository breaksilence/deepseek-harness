# Agent Note：在请求尾部主动交付知识

Status: proposed

[English](2026-10-30-active-knowledge-delivery.md) | 中文

## 问题

[晋升门后的事实](../../implemented/architecture/2026-10-30-knowledge-brain-facts-and-gate.zh.md)只在模型调用工具时才交付内容。而一个不知道某条约束存在的模型不会去问：它会在没有幂等键的情况下重试扣款、把汇率写死、在前端累加金额，**从不形成"那条事实能回答的问题"**。在 8 个记录任务上，同一个模型不给交付时只有 3/10 的方案带上了该约束，把索引追加到尾部后有 9–10/10 ——约束是存在的，只是没人去问。

普遍注入不是选项：没有会话事件就违反"模型可见即被记录"，而且会在不依赖历史内系统更新的路由上重写请求前缀。

## 提案

只有当扫描命中"作用域匹配当前轮次、且话题一致通过"的事实时，才把一份交付块**追加在请求末尾（最后一条消息之后）**。发送请求之前写入一个会话事件，携带被交付的 id 与 span，使回放能精确重建模型看到的内容。扫描为空时不注入，另有一个开关整体关闭这条路径。

交付块**先只给索引行**。信任报告与正文仍留在工具后面——因为"比索引行更贵的交付"没有被证明能更频繁地改变方案。

## 支撑这条形状的证据

- **尾部是唯一实测缓存安全的形式**：追加在前缀之后保留了 1,743 个 prompt tokens 中的 1,536 个（88.1%），而插到提示中部会让缓存命中降到 0。
- **索引行很便宜**：一次扫描加一次信任报告约一百 tokens，约占工作上下文的 0.1%。
- **交付会改变方案**：人工标注显示，不给知识时 30% 的方案带约束，给索引 90%，给索引加正文 100%；另一个不依赖判据的度量（答案是否包含该事实的独有短语）从 12.5% 升到 87.5%。
- **这些证据不能区分"只给索引"与"索引加正文"**：差别是十个任务里的一到两个。

## 考虑过的其他方案

**命中即交付全文。** 每轮上下文成本最大，而收益与只给索引无法区分。

**注入到系统提示。** 会重写路由依赖的前缀，而上文的缓存实测说明了代价。

**用一个 skill 教模型去问。** 更便宜且现在就能做，但这里的失效模式是"模型不知道约束存在"，光靠指令到不了它。

## 验收标准

- 扫描无命中的轮次发出的请求，与今天的请求**逐字节相同**。
- 扫描有命中的轮次把索引行追加在最后一条消息之后，且不出现在请求的其他位置。
- 会话日志携带被交付的 id 与 span，回放该日志能精确重建交付块；若交付块在日志未变的情况下改变，快照测试必须失败。
- 关闭开关后，请求恢复为今天的逐字节相同状态，且不触碰语料。
- 在人工标注的任务集上，交付索引使"方案带上约束"的比例高于已记录的不交付基线；各臂顺序打乱，并同时报告两种判据（人工标注与短语检查）。
- 信任报告与正文仍然只能通过工具获取；交付块对每条事实最多增长一行。

## 风险

**错误的交付比不交付更糟**：无论适用与否，这块内容都在请求里，而读到它的模型会照做。作用域匹配看不出某条事实昨天已被取代，因此尾部交付的过期事实会比模型主动询问时得到更坚定的执行。

**会话事件是一份持久契约。** 如果交付块不能被日志逐字节重建，回放与快照测试就不再说它们所声称的东西；那种情况下应当**移除该功能**，而不是记录一个近似版本。

**上下文成本在每个触发的轮次都要付**，而收益只在"约束真的重要"的任务上被测量。如果触发条件在多数轮次成立，成本是连续的，收益不是。

## 实现前必须回答的问题

**触发条件用哪个**：任何扫描命中，还是只有"碰到作用域内路径但没有点出话题"的轮次。后者正是工具服务不到的情形，也是错误交付最不容易被发现的情形。

**止损线是什么**：如果在上文的人工标注协议下，被交付的块没能改变方案；或者会话事件无法被精确回放，则该功能**被移除而不是被调参**。
